# Proxy Share 项目维护

## 开始任务

1. 完整阅读仓库根目录的 `ARCHITECTURE.md`，再搜索和打开目标代码。
2. 运行 `git status --short` 和 `git log -5 --oneline`，识别已有改动；不得覆盖或混入用户的无关改动。
3. 根据地图定位模块。若地图与代码不符，以代码为准，并在本次任务中修正地图。

## 实施与验证

- 保持原生 WinForms、.NET Framework 4.0 和零第三方运行时依赖，除非用户明确改变约束。
- 使用 UTF-8 编辑源码，使用 `apply_patch` 修改文本文件。
- 修改后运行 `cmd /c compile.bat`；涉及布局时检查最小、默认、最大客户区，涉及代理时避免在验证中擅自改变用户系统代理。
- 完成后更新 `ARCHITECTURE.md`：仅记录长期有效的结构、职责、数据流、约束和定位提示，不记录流水账。
- 若新增入口、类型、资源、构建步骤或关键行为，必须同步对应地图章节；纯文案或不影响定位的小修可确认地图无需改动。

## 自动判断提交

先检查 `git status --short` 和 `git diff --stat`，只提交本任务产生且已经验证的完整改动。

满足任一条件时创建提交：

- 修改注册表、网络测试、构建配置或其他高风险核心逻辑。
- 完成一个独立功能、修复或重构，值得形成可回退节点。
- 待提交内容累计达到 3 个有意义文件或约 150 行净变更，并且属于同一目标。
- 用户明确要求提交。

遇到以下情况不提交：改动尚未完成、验证失败、包含无法分离的用户改动、仅有微小文案调整，或用户明确要求不提交。积压较多但主题不同，应按主题拆分提交，不得把无关改动打包。

## 提交纪律

- 提交信息必须使用简体中文，格式采用 `类型：简明说明`，例如 `优化：重构代理设置界面`、`修复：阻止非法端口写入系统代理`。
- 提交前再次运行相关验证并检查暂存区内容。
- 不得擅自执行 `git push`、创建远程仓库、修改远程地址或强制改写历史；只有用户明确要求时才推送。
- 任务结束时说明是否提交、判断依据、提交哈希与验证结果。
